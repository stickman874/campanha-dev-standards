# Agentic workflow tooling: do we need OmniRoute? — 2026-09-15

Context: 3-person AI-first dev team, Claude Code subscription (Pro/Max), builds small Next.js/Prisma
apps for Portuguese consultancy clients (client-code privacy matters), no server-side CI.

## Decision matrix

| Need | Claude Code native/plugins | opencode + subscription | OmniRoute | Plain scripts |
|---|---|---|---|---|
| **1. Living/organized docs** | `CLAUDE.md` + [Skills](https://code.claude.com/docs/en/skills) load on-demand; this repo's own `core:doc-keeper` / `core:docs-consolidate` pattern (hook/skill-driven doc refresh) is the standard approach. No first-party "docs stay in sync" plugin exists. | Same idea, model-agnostic — opencode agents can run the same "update docs" skill/prompt. No unique advantage. | Does nothing for this — it's a routing proxy, not a docs tool. | A pre-commit/`Stop`-hook script that greps for stale doc markers, or a scheduled `/loop` task, covers it at near-zero cost. |
| **2. Code security assurance** | **Best covered natively.** Anthropic's official `security-guidance` plugin (in-session, free-tier included) does per-edit pattern checks (no model cost) + end-of-turn/commit agentic reviews (Opus 4.7 by default, billed as normal usage) — [docs](https://code.claude.com/docs/en/security-guidance). Layer with `/security-review` and the `claude-security` plugin for deeper scans, and Code Review for PRs (Team/Enterprise only). None of this replaces SAST/secret/dependency scanning. | No equivalent first-party security-review plugin; would need to wire the same free tools manually. | Not relevant — a proxy doesn't scan code. | **Free stack, CI-independent, no subscription burn:** [gitleaks](https://github.com/gitleaks/gitleaks) as a pre-commit hook (secret scanning, sub-second, runs on the dev's machine — no GitHub Actions needed), [Semgrep](https://semgrep.dev) (SAST) and `npm audit` / [Trivy](https://trivy.dev) (dependency/CVE scanning) as local pre-push hooks or `husky`/`lint-staged`. This combo replicates ~80–90% of GitHub Advanced Security at zero license cost per a 2026 comparison. |
| **3. Cross-dev consistency (design tokens, no hardcoded colors)** | Claude Code enforces nothing on its own; a project `CLAUDE.md` rule is guidance, not a gate — agents can ignore it. | Same — opencode has no built-in design-token linter either. | Not relevant. | **ESLint is the real answer.** [`eslint-plugin-better-tailwindcss`](https://github.com/schoero/eslint-plugin-better-tailwindcss)'s `no-hardcoded-colors` rule forbids raw color values (`bg-[#ff5733]`) and pushes toward design tokens — confirmed to exist as a real, maintained rule (also usable via Oxlint's jsPlugins layer). Wire it into a pre-commit hook (`husky` + `lint-staged`) so it blocks locally, since there's no CI to gate on. |
| **4. Claude usage exhaustion (subagents burn the same quota)** | **Confirmed by Anthropic docs, not just anecdote:** the `/usage` breakdown explicitly attributes recent usage to "skills, subagents, plugins, and individual MCP servers" as a share of **the same plan limit** ([costs docs](https://code.claude.com/docs/en/costs)). Agent teams (multiple parallel Claude Code instances) use **~7x more tokens** than a single session. Mitigations that exist today: route subagents to Haiku (`model: haiku` in subagent config or `CLAUDE_CODE_SUBAGENT_MODEL`), buy "usage credits" past the plan cap (still billed), `/usage` to monitor, `/clear` aggressively, and Explore subagent is capped at the parent's model (never more expensive). There is **no way to route subagent work to a different, non-Anthropic provider from inside Claude Code** — it's all one meter. | **This is opencode's structural advantage.** opencode is provider-agnostic: it can dispatch cheap/free-model subagents (DeepSeek, Kimi, local models, etc.) that **do not touch the Claude subscription at all**, only escalating to Claude when needed. It *can* technically authenticate with a Claude Pro/Max OAuth login (community plugins like `opencode-anthropic-auth` exist) — **but Anthropic's consumer Terms of Service now explicitly ban this**: OAuth tokens from Free/Pro/Max plans are authorized "exclusively for Claude Code and Claude.ai," and Anthropic added **server-side enforcement in Jan 2026** that hard-errors third-party use ("This credential is only authorized for use with Claude Code and cannot be used for other API requests") — [reporting on the Feb 2026 policy update](https://winbuzzer.com/2026/02/19/anthropic-bans-claude-subscription-oauth-in-third-party-apps-xcxwbn/). So opencode cannot legitimately extend Claude subscription quota; it must use a paid Anthropic API key (metered separately from the subscription) or non-Anthropic models via its own **Zen** gateway (pay-per-token, no subscription, ~$10/mo "Go" tier bundles ~$60 of usage — [opencode.ai/docs/zen](https://opencode.ai/docs/zen/)). | OmniRoute's whole pitch is exactly this: quota-aware auto-fallback across "Subscription → API Key → Cheap → Free" tiers, one OpenAI/Anthropic-compatible endpoint ([README](https://github.com/diegosouzapw/OmniRoute)). Its "Subscription" tier implies reusing consumer OAuth tokens across tools — the same practice Anthropic's Feb 2026 ToS update forbids and enforces server-side. Its "Free" tier routes to free-tier third-party model pools (e.g. Groq, SiliconFlow) — **client code privacy risk**: OmniRoute's own docs say the client itself doesn't exfiltrate telemetry, but by design your prompts (containing client code) go to whichever free/cheap backend it picked, each with its own data policy — unacceptable for consultancy client code without per-client vetting. | Cannot solve quota exhaustion — it's a metering problem inherent to the subscription model, not a routing gap. |
| **5. Codex review credit exhaustion (hard blocks)** | N/A directly, but the **official OpenAI `codex-plugin-cc`** plugin (Apache-2.0, installs inside Claude Code — [repo](https://github.com/openai/codex-plugin-cc)) is the first-party bridge: `/codex:review`, `/codex:rescue`, etc. It explicitly **supports ChatGPT subscription auth (including the Free tier) as an alternative to API credits** — [OpenAI help center](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) confirms ChatGPT sign-in draws on the plan's included usage (5-hour rolling window shared across Codex CLI/web/IDE), separate from pay-per-token API billing. So switching the team's Codex review step from **API-credit auth to ChatGPT-subscription auth** removes the "hits paid quota and hard-blocks" failure mode for the review itself (it now hits the ChatGPT plan's rolling window instead, which resets and doesn't need top-ups). Known footgun: the plugin's `--enable-review-gate` "stop hook" can create Claude↔Codex review loops that rapidly burn **both** parties' usage — [GitHub issue #306](https://github.com/openai/codex-plugin-cc/issues/306) confirms this is a real reported failure. | opencode doesn't run Codex reviews; irrelevant to this specific need beyond being able to dispatch a cheap-model reviewer as an alternative to Codex entirely. | OmniRoute's proxy model, plus Codex CLI's documented support for a custom `base_url`/`model_provider` in `config.toml` ([OpenAI config docs](https://github.com/openai/codex/issues/11698), [morphllm guide](https://www.morphllm.com/codex-provider-configuration)) — Codex CLI *can* be pointed at any OpenAI-Responses-API-compatible endpoint, including an OmniRoute-fronted one. This is a real, working escape hatch technically, but re-introduces the same free-tier-pool client-code-privacy problem as need 4 if the alternate endpoint is a third-party free pool. | Simplest fix that needs no new tooling: just switch Codex CLI auth from an API key to `chatgpt` (subscription) login, per OpenAI's own docs. |

## Bottom-line verdict

**(a) Is OmniRoute needed or redundant?** Redundant for this team, and actively risky for two of the five needs:
- For need 4 (Claude quota), its "Subscription" fallback tier assumes reusing OAuth tokens across tools, which is now **explicitly against Anthropic's ToS and server-enforced** since Jan/Feb 2026 — using it that way risks the team's Claude Code access being blocked, not just a policy technicality.
- For needs 4/5, its "Free" tier routes client code to third-party free-tier model pools — a direct conflict with the stated client-privacy requirement.
- Everything OmniRoute does that's *safe* to use (a single compatible endpoint, provider fallback using **paid API keys you own**) is already achievable more simply: opencode natively supports multiple providers/BYOK, and Codex CLI already supports a custom `base_url` without OmniRoute in the middle. OmniRoute adds a self-hosted gateway to operate and trust with client data for no capability this team actually needs safely.

**(b) Does opencode + the Claude subscription suffice?** Partially, and only if used correctly:
- opencode **cannot legally stretch the Claude subscription** (ToS-blocked OAuth reuse) — so it does *not* solve need 4 by "sharing" the Claude plan. It solves need 4 differently: by moving routine/cheap subagent work to non-Anthropic models paid separately (Zen pay-per-token or BYOK to other providers), so those tasks stop consuming Claude quota at all. That's a real, useful lever — but it's an added cost/ops surface (managing a second provider relationship and privacy vetting for whichever model handles client code), not a free multiplier of the existing subscription.
- opencode has no advantage for needs 1–3 and 5; Claude Code's native/official plugins and plain free tools cover those better or equally well.

**(c) Minimal stack for these 5 needs**, all usable without server-side CI:
1. Docs: Claude Code Skills + a scheduled/hook-driven "refresh docs" routine (this repo's existing `doc-keeper`/`docs-consolidate` pattern). No new tool.
2. Security: install Anthropic's **`security-guidance` plugin** (free, in-session) + local pre-commit/pre-push hooks running **gitleaks + Semgrep + `npm audit`/Trivy** — all free, no CI needed.
3. Consistency: **`eslint-plugin-better-tailwindcss`**'s `no-hardcoded-colors` rule (or the design-token-equivalent for whatever styling approach is used) wired into `husky`/`lint-staged` pre-commit.
4. Claude quota: use Haiku for subagents (`CLAUDE_CODE_SUBAGENT_MODEL`), avoid Agent Teams (≈7x cost) for routine work, monitor `/usage`; if that's insufficient, add **opencode with a separate BYOK/Zen budget** for genuinely cheap/bulk tasks only — never as an OAuth "subscription passthrough."
5. Codex credits: switch the official **`codex-plugin-cc`** to **ChatGPT-subscription auth** instead of API-key auth, and disable the auto `--enable-review-gate` stop-hook loop to avoid runaway consumption.

**Uncertainty flags:**
- Whether Claude Code's own `security-guidance`/end-of-turn reviews meaningfully overlap with, or should replace, Codex's `/codex:review` for this team wasn't settled by primary sources — both exist and are complementary per Anthropic's own "how this fits" table, but the team should pilot one before running both (each burns its respective quota).
- opencode's exact current stance on Claude OAuth (whether third-party plugins attempting it still function despite the Jan 2026 server-side block) wasn't independently re-verified against opencode's own docs beyond secondary reporting — treat "opencode + Claude subscription" as **not viable** unless the team confirms directly, rather than risk an account action.
- Trivy vs alternatives and exact `eslint-plugin-better-tailwindcss` maintenance status (last release cadence) weren't checked beyond npm/GitHub listing pages found via search.
